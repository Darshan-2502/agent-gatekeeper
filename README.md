## 1. Project Overview

The **Agent Gatekeeper** is a deterministic, offline-capable security and governance gateway that intercepts and evaluates requests submitted by customer-owned autonomous AI agents (e.g. personal trip planners, automated booking assistants) before they interact with Air India's operational and financial systems.

For every incoming request, the gatekeeper evaluates an authoritative 8-rule policy waterfall and returns exactly one of three decisions:
- **`ALLOW`** — The request is permitted to execute autonomously.
- **`ASK CUSTOMER`** — The request is paused, generating a time-limited (10-minute) confirmation token for human approval.
- **`BLOCK`** — The request is rejected outright, referencing the violating policy rule.

## 3. The Authoritative Rules (R1 – R8)

Rules are evaluated strictly in priority order from **R1** to **R8**. Evaluation terminates at the first matching rule.

| Rule | Decision | Plain-English Specification |
|---|---|---|
| **R1** | `BLOCK` | The agent is not registered in the system, OR the action is not one of the four allowed airline actions (`view_fares`, `book`, `change`, `refund`), OR a financial action arrives without a positive amount above zero. |
| **R2** | `BLOCK` | The agent has an active revocation timestamp (`revokedAt != null`). Revocation is permanent. |
| **R3** | `ALLOW` | The action is read-only (`view_fares`), the agent is registered, not revoked, and its mandate has not expired. |
| **R4** | `ALLOW` | A financial action (`book` or `change`) with amount &le; Rs. 10,000 and &le; the agent's individual per-transaction cap, with a valid mandate, matching customer identity, and velocity &lt; 3 transactions in the last rolling 24 hours. |
| **R5** | `ASK CUSTOMER` | A financial action (`book` or `change`) with amount &gt; Rs. 10,000 OR &gt; the agent's individual per-transaction cap (with valid mandate, matching customer, and velocity within limit). |
| **R6** | `ASK CUSTOMER` | Any refund request (`refund`), regardless of amount (with valid mandate, matching customer, and velocity within limit). |
| **R7** | `BLOCK` | The agent's mandate has expired (`validUntil < now`), OR the agent was registered under a different customer identity than the one submitting the request. |
| **R8** | `BLOCK` | Velocity limit exceeded: The agent already has 3 or more money actions (`ALLOW` or `ASK CUSTOMER`) recorded in the rolling 24-hour window. |

### Rationale: Why Rs. 10,000?
> An ordinary Air India domestic one-way sits between roughly Rs. 3,500 and Rs. 9,000, so Rs. 10,000 clears a normal booking without a prompt, while business class, international sectors, multi-passenger carts and stacked change fees always stop for one tap of confirmation.

## 4. How to Run the Prototype

### Option A: Interactive Browser Dashboard (`index.html`)
- **Zero build step, zero dependencies, zero network required.**
- Simply double-click `index.html` or open it in any modern browser (Chrome, Edge, Firefox, Safari) using the `file://` protocol.
- Features available in the UI:
  1. **Incoming Request:** Select an agent, choose an action, input an amount, and submit to see real-time color-coded decisions.
  2. **Agent Register:** Inspect active, expired, and revoked agent mandates. Use the "Revoke" button to test permanent cryptographic-style revocation. Register new agents with custom mandate durations and caps.
  3. **Waiting for Customer Confirmation:** Any decision yielding `ASK CUSTOMER` generates a 10-minute token (`CONF-XXXXXX`). Click "Approve" or "Decline" to log human-in-the-loop outcomes.
  4. **Policy Rules:** Live interactive table explaining R1 through R8 along with the Rs. 10,000 threshold justification.
  5. **Audit Log:** Chronological, tamper-evident audit history showing sequence numbers, timestamps, actions, amounts, decisions, rules, and human confirmations. Exportable directly as **CSV** or **JSON**.
  6. **Self-Test:** Execute all 8 test cases against a sandbox data replica with a single click, viewing immediate PASS/FAIL status without polluting live operational audit logs.

## 5. What to Change Before Submitting

If submitting under your own personal academic details or adapting for a different airline/client:
1. **Enrolment Number:** Update `ENROLMENT_NO` inside the `CONFIG` object in `index.html` (and tab title / header).
2. **Company Name:** Update `COMPANY` in `CONFIG` if adapting to another enterprise.
3. **Financial Limit & Velocity Limit:** Update `MONEY_LIMIT` and `VELOCITY_MAX` in `CONFIG`. Note that `10000` is defined strictly in `CONFIG` and nowhere else in the codebase.
4. **Customer Name:** If required by your instructor, update the default customer name `A. D. Keshri` in the seed records and default input fields.
